# rules.md — Универсальные правила проектирования архитектуры (Bootstrap)

Этот файл действует ТОЛЬКО на этапе создания каркаса проекта по `idea.md`.
После того как пользователь подтвердит структуру папок, модули и интерфейсы, создай постоянный файл системных инструкций (`CLAUDE.md` / `AGENTS.md` / `.cursorrules`) под утверждённую архитектуру и **удали `rules.md`**.

## 1. Порядок работы (Architecture-First)
1. Прочитай `idea.md` и выдели:
   - независимые домены/подсистемы;
   - модели данных и конфигурации;
   - слой отображения (UI / рендер) и точку входа.
2. Спроектируй и создай:
   - дерево папок и каркасные файлы (типы, структуры/компоненты, события, сигнатуры функций/систем с заглушками `todo!()` / пустыми телами);
   - карту проекта `ROADMAP.md` с точным путём и зоной ответственности каждого файла.
3. **НЕ пиши полную бизнес-логику** до явного подтверждения структуры пользователем.

## 2. Универсальные принципы модульности
- **Разделение по слоям и доменам**:
  - `core/` — общие состояния, типы, события и контракты между модулями;
  - `modules/` (или `features/` / `services/` / `plugins/`) — каждый домен в отдельной папке со своими данными, логикой и событиями;
  - `data/` / `assets/` — конфиги, балансы, описания сущностей (данные отделены от кода);
  - `ui/` — только отображение состояния и отправка команд/событий, без игровой или бизнес-логики;
  - `utils/` — чистые функции-хелперы без глобального состояния.
- **Тонкая точка входа**: корневой файл (`main.rs`, `App.tsx`, `Main.gd`) отвечает **только** за инициализацию и подключение модулей. В нём запрещено держать логику фич.
- **Лимит размера файла**: целевой размер любого файла — **до 250–350 строк** (жёсткий порог — 400 строк). Если модуль больше — заранее дроби его на подмодули.
- **Изоляция и слабая связанность**: модули не лезут во внутренности друг друга напрямую — взаимодействие строится через публичные интерфейсы, события/очереди команд или общие модели.
- **Симметрия без дублирования**: если в системе есть одинаковые стороны/режимы (например, Игрок и Бот), они работают через единую логику и общий маркер стороны, а не через копипасту кода.
